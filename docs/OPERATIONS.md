# Operations and recovery

Use the private installation receipt for exact source, host/installation,
config/state paths and native service name. Refresh actual evidence on request;
a branch, old snapshot or enabled flag does not prove a healthy service.

## Inspect

On Mac, run the selected installed source's diagnostics overview, host-claims
and publications actions. Use local_agent.repository.admin list for projects.
Inspect --help before changes. On Debian/Pi use linux_agent/pi_agent status
with the actual --config and --state. On Termux use the verified bundle's
termux_agent status or diagnose. Native service managers are launchd,
user-systemd and private runit respectively.

## STOP and uncertain work

Global emergency disable overrides intake. Linux/Pi use the private
EMERGENCY_STOP marker and disable action; Termux exposes stop. Mac uses its
operator emergency controls. Inspect current help and the private receipt.
Keep claims/results and inspect active workers plus inherited leases before
maintenance. Do not kill admitted owner work to obtain a drain.

Saved results retry publication without command execution. Uncertain effects
remain UNKNOWN. Never delete a claim, change a task ID or clear history to
force replay. Corrupt state, changed identity and unavailable trusted evidence
fail closed. Exactly addressed invalid Linux project input receives a durable
invalid_task_file rejection without crashing the service.

## Git metadata recovery

Mac managed control Git can recover exact Finder .DS_Store metadata with a
checkout-local exclude entry. Pre-boot shallow.lock recovery requires old
mutation timestamps, matching shallow metadata, no open holder, stable safe
file identity and durable fsynced backup. Reading-induced atime changes are
not mutation. Current-boot, changed, unrelated or uncertain locks stay untouched.
Never broaden this to index locks, arbitrary files or owner checkout cleanup.

## Update and rollback

Use an independent native operator after exact-source gates, identity checks,
admission-first drain, actual execution/resource exclusion, durable backups
and a runnable baseline. Update selected hosts sequentially. Verify new
PID/source and a new exact-target Git result after switching.

A first installation can roll back to stopped/disabled while preserving state.
An upgrade needs real independent previous source/runtime. Historical one-shot
pilot migration tools are not repeatable customer installers. Never restart or
update through the Agent's own task, or restore old ledgers over newer work.

Uninstall disables only the selected service after STOP/drain. Retain private
keys, config, task/results and user repositories. Deleting retained valuable
data requires a separate explicit customer decision.
